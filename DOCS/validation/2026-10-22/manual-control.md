# 수동 진행 전환과 음성 제거 검증

> [!note] 최신 요청 반영
> 앞부분은 전환 당시 기록이다. 현재 동작·최종 파일은 마지막 **최신 확장 — 사진·주제·음향·실행 바로가기**와 **문제 저장·확정 번호·번외 목록 복원**을 따른다. 대문에서 시작하며 주제2초 후 문제/타이머(1~5번10초/6번부터5초), 노래 문항은 시간 표시 없음이다. 공식 프리티걸 YouTube와 합성 음향만 사용하고 음성·TTS는 없다.

사용자 요청: “음성은 다 지우고, 내가 컨트롤 하면서 문제내고할 수 있도록”. 상품 소개와 19문항을 유지하고 음성·공동사회자를 제거했다.

## 구현

- 수동 상태 모델 `manual-model.js`와 DOM·저장·렌더링 담당 `standalone.js`를 분리했다. 인터페이스와 단계별 기준은 [[roadmap#현재 우선 작업 — 혼자 진행하는 수동 퀴즈]] 참고.
- 상품 소개·준비 화면·① 문제 공개·선택적 타이머·일시정지/계속·② 정답 공개·③ 다음 문제·이전 문제·문제 선택·가리기·종료를 직접 제어한다.
- 문제 공개는 타이머를 시작하지 않는다. 타이머 종료는 정답을 공개하지 않는다. 리모컨은 타이머 진행 중 다음 단계로 넘기지 않으며, 정답 공개 버튼으로 직접 조기 마감할 수 있다.
- 녹음 불러오기·TTS·기기 내 음성 인식·숫자 낭독·배경음/효과음·대본 편집과 AI 공동사회자 표시를 실행 HTML에서 제거했다. `tools/offline-media.js`를 삭제하고 빌드에서 미디어 모듈 내장을 없앴다.
- 저장 키는 유지한다. 기존 문제·보기·이미지·해설·메모·출처·손 방향을 복원하며 음성 설정과 낭독 대본은 사용·저장하지 않는다. 기존 저장 16/18문항을 자동으로 19문항으로 덮어쓰지 않는다.

## 음성 파일 삭제

현재 프로젝트의 원본 WEBM, 참고 WAV(루트·voice-output·시험용), GPT-SoVITS 준비 ZIP 2개와 준비 대본·안내 파일, 별도 다운로드 clone의 생성 WAV 38개 및 manifest 2개를 포함해 **50개 파일**을 삭제했다. 정확한 삭제 파일명·크기는 Git 제외 폴더 `data/manual-migration/removed-voice-files.json`에 기록했다.

폴더 일괄 재귀 삭제는 자동 승인 검토에서 차단되어, 확인된 파일명만 사용하는 개별 `Remove-Item -LiteralPath`로 범위를 좁혀 삭제했다. 각 파일의 부재를 확인했고 두 작업 폴더에서 `.git`·`node_modules`를 제외한 WAV/MP3/WEBM/OGG/M4A/FLAC 활성 파일 잔존은 0개다. 상품 원본 가격표와 상품 일러스트는 보존했다. GitHub 원격·Git 커밋 이력·원래 다른 위치의 저장소는 변경하지 않았다. 따라서 별도 clone은 이제 원격 그대로의 clean 사본이 아니라 음성 파일이 제거된 상태다.

## 실제 브라우저 검사

로컬에서 HTML 한 파일만 제공하는 `http://127.0.0.1:4179/`를 사용했다. 파일 URL 직접 열기나 실제 장비 확인으로 확대하지 않는다.

1. 1366×768에서 새 수동 UI, 상품 소개, 19문항 목록을 확인했다.
2. ① 문제 공개 직후 문제·O/X·손 방향 표시, 타이머 시작 전 안내 문구, 정답·공동사회자 비노출을 확인했다.
3. 타이머 시작 → 10초 종료 뒤에도 정답 비노출 → ② 정답 공개 → ③ 다음 문제에서 2번 문제로 이동과 타이머 자동 시작 없음을 확인했다.
4. 4번 해피 이미지 로딩과 공동사회자 없음 확인. 초기 화면과 1번 위치 복원.
5. 최종 UI를 다시 빌드·새로고침한 뒤 상품 소개·첫 문제 화면을 재확인했다. 1366×768에서 타이머 버튼 하단 약 654px로 주요 제어 버튼들이 화면 내에 표시된다. 관리자 전체 페이지에는 설정 영역을 위한 세로 스크롤이 있다.
6. 콘솔 오류·경고 로그 조회 0건. 임시 브라우저 크기 변경을 해제했다.

## 사용자 요청에 따른 화면 직접 재확인

Computer Use로 최종 HTML 미리보기를 사용자에게 보이도록 열고, ① 문제 공개 → ② 정답 공개 → ③ 다음 문제를 직접 클릭했다. 1번 문제에서 정답 공개 전 정답 비노출·타이머 자동 시작 없음을 확인했고, 정답 공개 후 2번으로 이동한 다음 이전 버튼으로 1번에 돌아왔다. 화면은 1번 문제가 표시된 상태로 열어 두었다. 콘솔 오류·경고 조회는 0건이었다.

독립 읽기 검토에서 원본 JSON과 실행 HTML의 19문항 전체 객체가 동일함을 확인했다. 지문·보기·정답·해설·제한시간·순서뿐 아니라 이미지·메모·출처도 일치한다. 실행 HTML SHA-256은 위 최종 해시 그대로이며 이 재확인으로 코드·문제·HTML을 수정하지 않았다.

## 추가 기능 — 문제 순서 편집

2026-10-22 사용자 요청으로 위·아래 이동과 원하는 번호 이동을 추가했다. `moveQuestion`은 원본 배열을 바꾸지 않고 문제 전체 객체를 새 배열에서 이동한다. 컨트롤러는 `draft`에만 반영하고 상단 **새 순서·편집 적용** 또는 하단 **문제 적용** 시 진행 목록과 저장소에 반영한다. 기본 문제 JSON의 19문항 전체 객체·원래 순서는 그대로이며, 실행 HTML 내 기본 데이터와도 완전히 동일하다.

- 회귀 검사 **18/18**, ESLint·단독 HTML 빌드·`git diff --check` 통과. 문제 객체·미적용 편집·이미지·메모 보존, 적용 전 진행 목록 불변, 적용/저장 복원, 잘못된 번호와 편집 중 Space 단축키 차단을 확인했다.
- 독립 읽기 리뷰에서 새 이동 버튼의 Space가 진행 단축키에 걸리는 문제를 찾아 `#editor` 내부 키 입력을 진행 단축키에서 제외했다. 실제 브라우저에서 Space가 순서 이동만 수행하고 공개 화면은 준비 상태로 유지됨을 확인했다.
- 사용자 화면과 저장소를 분리하기 위해 `localhost:4179`에서 검증했다. 2번 위로 이동 → 1번 아래로 이동으로 복원, 4번 해피 문제를 1번으로 번호 이동 → 적용 → 새로고침 후 유지 → 공개 시 해피 이미지 로딩과 정답 비노출 확인. 20번 입력은 오류 안내 후 순서 유지. 검사 후 원래 순서로 복원했다.
- 열린 사용자 화면의 편집 내용과 입력값을 읽어 미적용 변경이 없음을 확인한 뒤 최종 HTML을 새로고침했다. 사용자 화면에서는 원래 순서를 유지하고 상단 적용 버튼의 정상 동작을 확인했다. 편집 영역을 열린 상태로 남겼다. 콘솔 오류·경고는 0건이었다.
- 최종 HTML: **3,757,534바이트**, SHA-256 `c3adb9f45bf4823bc95f5d048e062df90f9a125227f5cc6c353d3804ae67a565`. 이전 절의 해시는 순서 편집 추가 전 기록이다.
- GitHub 업로드·배포는 수행하지 않았다. 실제 프로젝터·별도 팝업 검증 범위도 이전 기록과 동일하다.

## 추가 변경 — 상품 소개 시작 화면과 자동 타이머

2026-10-22 최신 요청에 따라 초기 화면을 상품 소개로 하고 상단 고정 **상품 소개 페이지 / 문제 진행 화면** 버튼을 추가했다. 문제 공개·다음 문제·이전 문제의 공개와 동시에 **현재 순서 1~5번은 10초, 6번부터 5초**의 타이머를 시작한다. 저장·가져오기·재정렬 후 적용에도 순서별 규칙이 적용되며 편집 제한시간은 읽기 전용이다. 상품/준비/선택/종료 화면으로 이동하면 타이머를 취소한다. 일시정지·가리기의 잔여시간 보존과 수동 정답 공개는 유지한다.

사용자 저장소와 분리된 `localhost:4179`의 노트북 1366×768 화면에서 확인했다. 실제 팝업/현장 장비 시험으로 확대하지 않는다.

루프백 서버의 신규시작/기존 재사용/다른 서비스 충돌 거부, health·HTML바이트·no-store·HEAD·404/405와 한글 경로 CMD 실행을 검증했다. 기존4179프로세스를 보존하고 임시 검증 서버만 정리했다. 바탕화면 `OX 퀴즈 시작.lnk` 생성과 대상/인수 검증을 완료했다.

## 문제 저장·확정 번호·번외 목록 복원

### 저장 원인과 수정

기존 편집은 메모리의 draft에만 있어 적용 전 새로고침 시 사라졌다. localStorage 쓰기 실패도 적용 성공 메시지에 가려졌다. ‘번호 임시’는 현재 번호 상태가 아니라 이전 문항의 review 메타데이터였다.

편집 문구·정답·순서를 기존 키 `ox-banquet-standalone-v1`에 자동 보관한다. 사진을 복제하지 않고 적용 목록을 참조하는 차이만 저장한다. **문제·순서 저장** 시 전체 문항 검증과 저장 성공을 먼저 확인한 뒤 진행 목록·드롭다운·선택0·편집 번호를 함께 갱신한다. 저장 실패는 현재 진행 목록을 유지하며 재시도 안내를 표시한다. 미완성 입력도 복원하며 손상된 편집 메타데이터는 정상 문제 목록을 중단하거나 덮어쓰지 않는다. 과거 임시 번호/배치 안내는 표시에서 제외하고 원본 메타데이터는 보존한다.

실제 `localhost:4179`에서 문구·정답 편집과 순서 이동 → 적용 전 새로고침 복원 → 저장 즉시 드롭다운 새 순서/선택0 → 새로고침 후 지문·정답·순서 유지까지 확인했다. 검증용 변경은 원래 입력/순서로 완전히 복원했다. 사용자 `127.0.0.1:4179` 맞춤20문항도119필드 전후 일치를 확인했다. [저장 검증](save-order-runtime.json), [저장 완료 화면](save-order-complete.jpg).

## 마스코트 재확인·제목의 띄어쓰기 줄바꿈

사용자가 기존 마스코트 이미지를 지적해 재확인했다. 기존은 코글의2D 리터치 이모티콘이다. 공식 [한전 챗봇](https://chat-online.kepco.co.kr/kepcoHappyBot/)과 [한전ON 사용 이미지](https://online.kepco.co.kr/cm/images/ico-chatbot.png), 공식 홈페이지 개인정보 안내 그림의 해피 표기 및 제작사의3D 기본형을 대조했다. 옛 케피·스포츠단 에너지보이·플랫폼 세이비를 해피로 바꾸어 넣지 않았다.

교체 자산은 [한국전력 사내 극장 안내영상 제작자 포트폴리오](https://kmong.com/portfolio/view/95381)의3D 전신 JPEG다. 1272×712·46,322바이트이며 KEPCO 로고가 있고 이름/정답 문구는 없다. 이미지를 재생성하거나 편집하지 않았다. 공식 사이트에서 배포한 원본 파일이라는 주장이나 CC 라이선스 주장은 하지 않는다. [출처·바이트·해시·권리 범위](../../../questions/assets/kepco-happy-3d.source.json).

`question-assets.js`가 이전 GIF의 전체 data URI가 정확히 일치하는 문항만 이미지 필드로 갱신한다. 이전 은행 기준의 편집 차이를 먼저 복원하므로 미적용 순서/정답/문구를 잃지 않는다. 이전 백업 JSON을 가져와 저장해도 새 이미지로 갱신한다. 사용자 사진·다른 문항·문구·보기·정답·해설·순서는 교체하지 않는다. 실제 사용자 맞춤20문항119개 편집 필드가 전후 완전히 일치했고6번의 새 JPEG1272×712 로딩을 확인했다. 이전 출처 메모 원문은 보존하되 표시 안내를 새 이미지 기준으로 정리했다.
