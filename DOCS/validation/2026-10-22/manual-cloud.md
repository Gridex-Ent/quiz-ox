# 수동 클라우드 퀴즈 로컬 검증

휴대폰 크기의 진행실과 별도 스크린을 하나의 수동 퀴즈 서버에 연결하는 구현을 로컬에서 검증했다. 현재 사용자가 편집한20문항을 보존했고, 문제·순서 저장, 서버 기준 진행/타이머, 번외 복귀, 관리자 전용 수령 기록과 스크린 음향 제어를 확인했다. **실제 Cloud Run/GCS 배포와 외부 휴대폰 접속은 아직 수행하지 않았다.**

## 범위와 책임

설계·단계·배포 조건은 [[manual-cloud-deploy]]에 기록했다. 기존 로컬 `OX퀴즈.html`과4179 서버, 기존 참가자 게임은 유지하고, 새 수동 서버를 별도4185 포트에서 검증했다.

| 모듈 | 책임·공개 인터페이스 | 검증 범위 |
|---|---|---|
| `web/src/offline/manual-model.js`·`presentation.js` | 기존 수동 전이와 공개 화면 생성 | 대문·상품·주제·타이머·노래 예외·번외 복귀 규칙 재사용 |
| `cloud/manual-service.mjs` | 관리자 명령, 서버 시각, revision·command ID, 관리자/스크린 DTO | 저장 전 ACK 금지, 중복/오래된 명령, 저장 충돌, 정답/명단 노출 방지 |
| `cloud/store.mjs` | 로컬 atomic 저장 / GCS generation 조건 저장 | 로컬 파일 및 가짜 GCS 저장소 테스트. 실제 GCS·IAM은 미검증 |
| `cloud/server.mjs` | PIN 세션·스크린 키·동일 출처 검사·HTTP 경계 | 로컬 HTTP 인증/권한과 실제 브라우저 연결 |
| 진행실·스크린 어댑터 | 명령 전송·상태 동기화·화면 렌더·음향 | 별도 브라우저 화면에서 실제 버튼 조작 |
| `tools/build-cloud.mjs` | `dist/cloud`의 로그인·진행실·스크린·초기 데이터 생성 | 맞춤20문항 전체 보존, 빌드/의존성 검사 |
| `cloud/Dockerfile`·`deploy/manual-cloud.ps1` | 전용 컨테이너/명시적 대상 배포 | 로컬 패키지·구문 검사 완료. 컨테이너·원격 배포는 미실행 |

> 후속 운영 기록: 실제 CompanyInfo Cloud Run 배포·GCS 저장·HTTPS 화면 검증과10/23 자정 예약은 [실제 클라우드 검증](manual-cloud-live.md)에 기록했다. 아래의 미배포·인증 대기는 이전 로컬 검증 시점의 상태다.

## 실제 브라우저에서 확인한 흐름

CUA로 로컬 HTTP 서버의 진행실과 별도 스크린을 조작했다. 진행실은 **390×844** 브라우저 viewport, 스크린은 **1366×768·1920×1080** viewport다. 휴대폰 크기 반응형 확인이며 실제 Android/iPhone 또는 실제 프로젝터를 사용한 결과는 아니다.

| 확인 항목 | 결과·원복 |
|---|---|
| 대문·상품 소개 | 시작 전 대문과 상품 페이지를 표시하고 상품 소개에서 문제로 전환했다. 상품7등급·28명·총200만원 안내 유지 |
| 첫 문제 | 첫 순서 **워밍업**이2초간 나타난 뒤 Q1과10초 타이머가 자동 시작됨 |
| 직접 진행 | 일시정지·정답 공개·다음 문제 조작을 진행실에서 수행하고 스크린의 같은 상태 확인. 시간 종료가 정답 자동 공개를 의미하지 않음 |
| 노래 문제 | 사용자 순서 Q2에서 카운트다운과 시간 표시가 없음을 확인 |
| 런북 | 넌센스 번외 문제를 공개한 뒤 본게임 Q2로 돌아가 원래 진행 위치를 복원함 |
| 편집·순서 확정 | Q3 임시 문구와 Q3/Q4 교환을 저장하고, 드롭다운 갱신 및 새로고침 후 같은 목록을 확인한 뒤 원래 문구/순서로 복원 |
| 사진·후반 시간 | Q3 테슬라, Q6 최신 한전 마스코트 사진 표시. Q6의5초 타이머와 일시정지 확인 |
| 수령 기록 | 가상 이름·전화번호 한 행을 입력하고 서버 저장 완료 후 새로고침 복원 확인. 검증용 행은 삭제하고 삭제 결과 확인 |
| 음향 제어 | 스크린에서 소리를 활성화한 뒤 진행실의 음소거/해제에 따라 별도 스크린 상태가 바뀌는 것을 확인 |
| 원이 공식 영상 | 사용자 Q7에서 보이는 공식 YouTube 플레이어와 **공식 영상 재생 중** 상태를 확인. 정답 공개 후 패널 숨김·정지 확인 |
| 1920 출력 | 스크린의 가로/세로 overflow가 모두 false임을 확인. 전체 문제별 모든 문구의 줄바꿈을 일괄 검증한 결과로 확대하지 않음 |

음향 상태와 영상 재생은 브라우저에서 확인했다. 실제 행사 스피커의 청취·음량·프로젝터 연결 품질은 확인하지 않았다. YouTube 재생에는 인터넷과 브라우저 재생 허용이 필요하다.

## 저장·인증·자료 보존

- 현재 사용자 문제집을 실제 GUI 문제 백업에서 확보해 `questions/kiee-a-2026-cloud-seed.json`으로 보존했다. 원본과 빌드 결과의 **20개 전체 객체가 일치**했고, UI 편집 검증 후 서버 문제집도 GUI 백업과 전부 같게 원복했다. 가상 수령 기록의 입력은0건이다. AI1번·노래2번·원이7번은 현재 사용자 순서이며 기본 오프라인 JSON의 번호와 다르다. 개인 수령 명단·세션·토큰은 seed에 포함하지 않는다.
- seed는 비어 있는 새 저장소의 초기값이다. 서버에 저장된 상태가 있으면 이를 우선하고 빌드 seed로 교체하지 않는다. 기존 로컬 브라우저의 문제집/명단을 클라우드에 몰래 옮기는 동작은 없다.
- 게임 명령과 문제 저장은 서버가 저장 완료를 확인한 뒤 성공 응답을 보낸다. revision·명령 ID와 GCS generation 조건으로 오래된 탭의 덮어쓰기/중복 명령을 막고, 저장 실패/충돌을 성공으로 표시하지 않는다. 실제 GCS 쓰기와 IAM이 검증됐다는 뜻은 아니다.
- 진행실은 PIN 로그인 후 HttpOnly 세션으로 접근한다. 운영 모드는 Secure 쿠키를 사용한다. 스크린은 별도 긴 키를 검사하고, 공개 DTO에 미공개 정답·전체 다음 문제집·진행 메모·수령 명단을 포함하지 않는다. 정답 공개 상태에서 해당 정답을 표시하는 기능은 유지한다.
- 수령 기록의 서버 저장 완료는 비동기 응답을 받은 경우에만 표시한다. 서버 ACK 전 입력은 **탭별 sessionStorage**에 보관해 해당 탭의 새로고침 후 복원하며, 저장 중 새 입력이 생겨도 이전 응답이 새 입력을 지우지 않는다. 서버 저장 전 창 닫기를 시도하면 브라우저의 이탈 경고를 요청한다. 탭을 닫은 뒤에도 미전송 입력이 영구 보관된다는 보장은 하지 않는다.
- 서버 재시작 시 저장된 진행 상태를 복원하며 진행 중이던 타이머는 정지 상태로 복구한다. 운영의 파일시스템 휘발성을 피하기 위해 `NODE_ENV=production`에서는 GCS 버킷 없이 시작하지 않는다. 로컬 개발 저장은 `data/manual-cloud/state.json`이다.

## 자동 검사·배포 패키지 검사

최종 수동 회귀90개·클라우드38개와 린트·두 빌드를 통과했다. [산출물 기록](manual-cloud-artifact.json)에 실행 범위, 원복 확인과5개 산출물의 SHA-256을 기록했다.

| 검사 | 결과·증거 경계 |
|---|---|
| `npm run test:offline` | 90/90 통과. 기존 수동 규칙·편집·음향·런북·수령 기록 회귀 |
| `npm run test:cloud` | 38/38 통과. 클라이언트9개·실제 controller 모듈의 VM 실행6개·서버23개. 서버 상태/저장·인증·HTTP 경계·DTO 검증이며 실제 GCS/Cloud Run 호출은 아님 |
| `npm run lint`·diff 공백 검사 | 통과 |
| `npm run build:cloud`·`npm run build:offline` | 통과. 클라우드 산출물과 기존 단독 HTML 재생성 |
| PowerShell 배포 스크립트 | AST 구문 검사, 파일별 diff 공백 검사 통과. 예약된 기존 `ox-quiz` 대상은 거부 |
| `-PrepareOnly` | 가상 프로젝트 이름으로 로컬 배포 계획·허용 목록 소스만 생성. gcloud 호출/클라우드 쓰기 없음 |
| 패키지·의존성 | 격리된 소스에서 `npm ci` → `build:cloud` → production prune → 서버·GCS SDK import 성공. 최신 패키지에서도 맞춤20문항 전체 일치 |
| 배포 소스 범위 | 허용 목록48파일. 개인 명단·runtime state·실제 환경 비밀·Git 이력·음성 파일 제외. 문서에는 공개 화면 스크린샷만 복사 |
| Docker·Cloud Build | Docker CLI는 있으나 Linux daemon 미실행. 실제 컨테이너 실행·Cloud Build 제출은 미검증 |

## 운영 반영·차단·다음 작업

| 상태 | 항목 | 남은 작업 |
|---|---|---|
| 구현·로컬 검증 완료 | 진행실/스크린, 사용자 문제집, 직접 진행, 저장·권한 경계 | 자동128개·린트·두 빌드 통과, 사용자 자료 원복 확인 |
| 준비 완료 | 전용 Dockerfile·배포 소스·명시적 PowerShell 절차 | 기존 리소스가 확정된 프로젝트에서 사전 조회 |
| 차단 | 실제 클라우드 대상/인증 | 퀴즈용 프로젝트 ID 응답 대기, gcloud 재로그인. 현재 기본 `orca-runtime-gridex`는 퀴즈 대상으로 선택하지 않음 |
| 미실행 | 실제 Cloud Run·GCS·IAM·HTTPS | 명시된 기존 버킷/서비스 계정/비밀/Artifact Registry로 배포하고 재시작·재접속 저장 검증 |
| 미검증 | 실제 휴대폰·현장 장비 | 휴대폰 LTE/Wi-Fi에서 진행실 접속, 노트북 스크린 동기화·스피커·프로젝터 리허설 |

자동 승인 검토가 가짜 gcloud CLI를 사용하는 **배포 통합 실행 검사**를 `blocked by policy`로 거부했다. 구체적인 사유는 제공되지 않았으며 해당 호출은 실행되지 않았다. 재시도나 우회는 하지 않았다. 이 제약은 인증 만료/대상 미확정으로 실제 배포를 수행하지 못한 사유와 별개다.

다음 단계는 프로젝트 ID를 확정하고 인증을 복구한 뒤 [[manual-cloud-deploy]]의 사전 조회·전용 배포·HTTPS 두 화면 검증을 수행하는 것이다. 이번 작업에서 기존 서비스·gcloud 전역 설정·4179 사용자 서버·원격 GitHub를 변경하지 않았다.
