# OX Quiz Cloud 사용자 매뉴얼

진행실에서 행사와 문제를 관리하고, 별도 스크린을 참가자에게 보여 주는 진행자용 안내입니다. **한 서버에 연결된 진행실과 스크린은 같은 행사 정보·문제·진행 상태·명단을 공유합니다.** 문제 편집은 한 진행실에서 맡는 편이 안전합니다.

## 1. 실행하고 로그인하기

운영 주소를 안내받았다면 해당 진행실에 접속해 로그인합니다. IAP가 설정된 환경에서는 허용된 Google 계정 인증 후 진행자 PIN을 입력합니다.

개발 PC에서는 Node.js 22.13 이상을 준비하고 프로젝트 폴더에서 실행합니다.

```powershell
npm ci
npm run dev
```

기본 주소는 `http://127.0.0.1:4190/`입니다. 터미널에 표시된 주소를 확인하세요. 개발 서버는 실행한 PC에서만 접속하도록 바인딩됩니다.

첫 실행에 무작위 접근 정보를 생성해 `data/development/access.json`에 보관합니다. 이 파일에서 진행자 PIN을 확인해 입력하세요. 다음 실행에도 같은 개발 프로필의 접근 정보와 상태를 사용합니다. 접근 파일·저장 상태·명단은 Git에 올리거나 공개하지 마세요.

## 2. 스크린 연결과 소리

1. 진행실 상단의 **프로젝션 창 열기**를 누릅니다. 창이 열리지 않으면 브라우저의 팝업 허용을 확인합니다.
2. 노트북에 외부 화면을 연결했다면 Windows 디스플레이를 **확장**으로 설정하고 스크린 창을 보조 화면으로 옮깁니다.
3. 스크린의 **전체화면** 또는 `F11`을 사용합니다. 진행실은 별도로 열어 둡니다.
4. 스크린에서 **스크린 소리 켜기**를 한 번 누릅니다. 이후 진행실에서 전체 소리·배경음악·음량을 제어합니다.

다른 기기에는 진행실의 스크린 링크를 전달합니다. 링크에는 연결 키가 포함되므로 참가자에게 공개 배포하지 마세요. 키 입력 화면이 나오면 진행실의 최신 링크로 다시 연결합니다.

공식 YouTube가 연결된 문항은 인터넷이 필요합니다. 자동 재생이 막히면 스크린의 재생 버튼을 직접 누릅니다. 키보드로 문제를 넘길 때는 **진행실의 문제 진행 화면에 포커스**를 둡니다. 공개 스크린은 읽기 전용입니다.

## 3. 행사 정보와 상품 준비

상단 **행사 설정**에서 다음 내용을 입력하고 **행사 설정 저장**을 누릅니다.

| 항목 | 입력 기준 |
|---|---|
| 행사명 | 필수, 80자 이내 |
| 행사일 | 선택, `YYYY-MM-DD` 형식 |
| 장소 | 선택, 120자 이내 |
| 안내 문구 | 선택, 200자 이내 |

저장 완료 안내를 확인하면 연결된 스크린의 대문과 종료 화면에 반영됩니다. 날짜·장소·안내 문구를 비워 두면 해당 내용은 생략됩니다. 행사 정보와 문제집은 별도로 관리하므로 새 행사를 준비할 때 기본 문항도 검토하세요.

### 상품 소개 이미지

같은 페이지의 **상품 소개 이미지** 영역을 사용합니다.

1. **이미지 파일**에서 PNG·JPEG·WebP·GIF를 선택합니다. 파일당 **4MiB 이하**입니다.
2. 미리보기를 확인하고 선택 사항인 **이미지 설명**과 **캡션**을 입력합니다. 각각 100자·200자 이내입니다.
3. **상품 이미지 저장**을 누르고 서버 저장 완료 안내를 확인합니다.
4. **상품 소개 페이지**를 열어 참가자 화면에 큰 이미지와 캡션이 표시되는지 확인합니다.

파일 선택과 미리보기만으로 서버에 저장되지는 않습니다. 기본 이미지에 새 설명·캡션을 적용하려면 먼저 사용할 이미지 파일을 선택하세요.

**기본 이미지로 복원하여 저장**은 기본값을 서버에 바로 저장합니다. **서버의 최신 이미지 불러오기**는 확인 후 현재 미저장 입력을 버리고 서버 값으로 돌아갑니다. 필요한 원본 이미지 파일은 따로 보관하세요.

행사 정보와 상품 이미지는 각각의 저장 버튼을 사용합니다. 상품 이미지를 바꾸어도 수령 기록의 7그룹·28칸은 유지됩니다.

## 4. 문제 문구·정답·순서 편집

문제 진행 화면 아래 **문제 준비 · 편집 · 백업**을 펼칩니다. 문구·보기·해설·정답을 수정하거나 **+ 문제 추가**, **삭제**를 사용합니다. 순서는 **↑ 위로 / ↓ 아래로** 또는 **이동할 번호 → 이동**으로 바꿉니다.

- 편집 내용은 현재 브라우저에 초안으로 자동 보관됩니다. 서버와 다른 기기에 반영하려면 **문제·순서 저장**을 눌러야 합니다.
- 저장 완료 후 확정 순서로 **문제 선택** 드롭다운이 갱신됩니다. 저장 중 추가로 편집했다면 안내에 따라 한 번 더 저장합니다.
- 문제집을 적용하면 **첫 문제의 준비 상태**로 돌아가고 타이머가 초기화됩니다. 진행 중 적용할 때는 중단 확인 창을 읽으세요.
- 첫 순서의 주제는 워밍업입니다. 일반 문제와 번외의 제한시간은 모두 10초이며, 노래 문항은 시간 표시 없이 진행합니다.

### 가져오기와 백업

**적용된 문제 백업**은 현재 서버에 적용된 문제집을 JSON으로 내려받습니다. **미저장 편집 초안은 포함하지 않습니다.** 초안도 필요하면 먼저 저장하거나 수정 문구를 따로 보관하세요.

**CSV / JSON 불러오기**와 **행사 기본 문제 불러오기**는 편집란 전체를 바꿉니다. 기존 목록 뒤에 자동으로 합치는 기능이 아닙니다. 먼저 필요한 내용을 보관하고, 가져온 목록을 검토한 다음 **문제·순서 저장**을 누릅니다. 사진·영상·메타데이터까지 보존할 때는 앱에서 백업한 JSON을 사용하세요.

다른 진행실에서 문제집이 바뀌었다는 안내가 나오면 현재 초안과 서버의 새 목록을 대조한 뒤 저장합니다. 여러 탭에서 동시에 편집하면 서로의 변경을 덮어쓸 수 있습니다.

## 5. 참가자에게 안내할 규칙

1. 문제가 나오면 정답을 생각합니다.
2. **시간이 끝나면 O는 주먹, X는 보자기로 손을 듭니다.** 선택형 문제는 첫 번째 보기가 주먹, 두 번째 보기가 보자기입니다.
3. 든 모양을 유지하고 진행자의 정답 공개를 기다립니다.

**주제 2초 → 문제 공개 → 일반 문제·번외 모두 10초** 순서로 자동 진행됩니다. 시간이 끝나도 정답은 자동 공개되지 않습니다. 노래 문항에는 카운트다운이 없으며, 진행자가 적절한 시점에 정답을 공개합니다.

주관식 번외는 손 모양 보기 대신 진행자의 안내에 따라 말로 답하는 방식입니다. 진행자 전용 팁은 문제 진행 화면의 **관리자 전용 정답 · 진행 메모 → 진행자 팁** 패널에서 확인합니다.

## 6. 진행 버튼

| 버튼·메뉴 | 동작 |
|---|---|
| 시작하기 / 상품 소개 페이지 | 상품 소개 화면 표시 |
| 문제 선택 | 선택한 문제의 준비 상태로 이동. 공개는 별도 조작 |
| ① 문제 공개 | 주제 2초 후 문제와 10초 타이머 시작 |
| ② 정답 공개 | 정답·해설 공개. 필요하면 타이머 중에도 직접 공개 가능 |
| ③ 다음 문제 | 정답 공개 후 다음 주제/문제. 마지막 문제 뒤에는 종료 화면 |
| ← 이전 문제 | 이전 문항을 주제 예고부터 다시 진행 |
| 일시정지 | 문제 타이머 또는 주제 예고 정지 |
| 타이머 계속 / 주제 예고 계속 | 멈춘 남은 시간에서 재개 |
| 타이머 다시 시작 | 시간이 끝난 일반 문제의 10초를 다시 시작 |
| 화면 가리기 | 검은 화면으로 가리고 진행 중 타이머 정지 |
| 준비 화면 | 현재 문제를 준비 상태로 되돌림 |
| 대문 | 첫 문제 위치로 돌아가 대문 표시 |
| 종료 화면 | 종료 화면 표시 후 상품 수령 기록으로 이동 가능 |

문제 화면을 가렸다가 다시 켜면 타이머는 직접 재개합니다. 진행 중이던 **주제 예고**를 가렸다면 가림 해제와 함께 남은 예고가 이어집니다.

행사 설정 페이지를 여는 것만으로 타이머가 정지하지는 않습니다. 진행 중 설정을 바꿀 때는 먼저 **일시정지**를 사용하세요.

## 7. 키보드·발표 리모컨

진행실의 **문제 진행 화면**에서 `PageDown`, `→`, `↓`, `Space`는 같은 진행 키입니다.

| 현재 화면·상태 | 진행 키를 한 번 누르면 |
|---|---|
| 대문 | 상품 소개 |
| 상품 소개 / 문제 준비 | 주제 예고 후 문제 공개 |
| 주제 예고 중 | 동작 없음 |
| 일반 문제 타이머가 흐르는 중 | 동작 없음 |
| 시간 종료 후 정답 대기 | 정답 공개 |
| 일시정지된 문제 | **정답 공개** |
| 노래 문제 공개 중 | 정답 공개 |
| 정답 공개 후 | 다음 문제. 번외는 본게임 복귀, 마지막 문제는 종료 |
| 종료 화면 / 화면 가림 | 동작 없음 |

`Esc`는 일시정지입니다. **일시정지 후 진행 키는 타이머 재개가 아니라 정답 공개**로 작동하므로, 재개할 때는 **타이머 계속**을 누르세요.

입력칸·문제 편집란·행사 설정·런북·수령 기록에서는 진행 단축키가 작동하지 않습니다. 키를 길게 누르거나 연타하지 말고 화면 반영을 확인한 뒤 다음 조작을 합니다.

## 8. 진행 런북과 번외 퀴즈

**진행 런북**을 열면 본게임이 일시정지됩니다. 저장된 번외 목록에서 골라 **선택한 번외 문제 출제**를 누르거나, 본게임 문제를 복사하거나, 즉석 주관식/OX를 작성할 수 있습니다.

번외도 주제 2초 후 10초이며 정답을 직접 공개합니다. 정답 공개 전의 관리자 미리보기와 진행자 멘트는 진행실에서만 확인합니다. 정답을 공개해도 진행자 전용 멘트는 스크린에 나오지 않습니다.

**본게임으로 돌아가기** 또는 번외 정답 뒤 **다음**을 누르면 원래 문제 위치·정답 공개 상태·남은 시간으로 복귀합니다. 본게임 타이머는 멈춘 상태이므로 필요하면 **타이머 계속**을 누릅니다. 번외 출제는 본게임 문제집과 순서를 바꾸지 않습니다.

## 9. 종료 후 상품 수령 기록

종료 화면에서 **상품 수령 기록**을 엽니다. 현재 폼은 **7그룹·총28칸**이며 이름과 전화번호를 입력합니다. 입력할 때마다 저장을 시도하므로 **클라우드에 저장했습니다** 안내를 확인하세요. 저장 실패 시 **클라우드에 다시 저장**을 사용합니다.

- **명단 JSON 백업 / 불러오기:** 입력 원문 보관·복원용입니다. 불러오면 현재 명단을 대체하고 저장합니다. 현재 폼과 같은 28칸의 JSON을 사용합니다.
- **CSV 내보내기:** 전달·정리용입니다. Excel에서는 전화번호 열을 텍스트로 지정해 불러오면 앞자리 0을 유지하기 쉽습니다.
- 문제 백업과 수령 명단 백업은 별도입니다. 명단은 공개 스크린에 표시되지 않습니다.

**행사명·날짜·장소·상품 이미지를 바꾸어도 이전 수령 명단은 자동으로 비워지지 않습니다.** 새 행사 전에 이전 명단을 별도로 백업하고, 남아 있는 이름·전화번호를 확인해 직접 비운 뒤 저장 완료를 확인하세요. 상품 소개 이미지 변경도 수령 폼의 등급·칸 수를 바꾸지 않습니다.

명단 파일에는 개인정보가 있으므로 접근을 제한해 보관하고 Git·공개 문서·스크린에 올리지 않습니다.

## 10. 저장 실패·다른 탭 충돌에 대응하기

| 안내·상황 | 대응 |
|---|---|
| 연결 끊김 / 저장 중 | 마지막 상태를 확인하고 연결 회복·저장 완료 안내를 기다립니다. 같은 조작을 연타하지 않습니다. |
| 로그인 만료 | 진행실에 다시 로그인한 뒤 현재 문제와 타이머를 확인합니다. |
| 행사/상품이 다른 화면에서 변경됨 | 작성 내용을 보관·대조한 뒤 **서버의 최신 설정/이미지 불러오기**로 기준을 갱신하고 다시 편집합니다. |
| 미저장 명단과 서버 명단이 충돌함 | 복구 안내에서 보관된 입력을 먼저 백업하고 최신 명단과 대조합니다. 복원 저장은 서버 명단을 바꿀 수 있습니다. |
| 이미지 형식·크기 오류 | 지원 형식과 4MiB 한도를 확인합니다. 오류가 나면 기존 이미지 입력을 유지합니다. |
| 이 탭에 임시 보관하지 못함 | 새로고침·창 닫기 전에 서버 저장을 완료합니다. 필요하면 작성 내용이나 원본 파일을 따로 보관합니다. |

행사·상품·미전송 명단은 같은 탭의 새로고침에 대비해 임시 보관을 시도합니다. 탭을 닫은 뒤의 복원을 보장하지 않습니다. 이미지가 크거나 브라우저 저장 공간이 부족하면 임시 보관이 실패할 수 있습니다. 닫기 경고가 나오면 저장 상태를 먼저 확인하세요.

### 행사 시작 전 마지막 확인

- 행사 정보·상품 이미지를 각각 저장하고 스크린에서 확인했습니다.
- 문제·정답·순서를 검토해 저장하고 적용된 문제집을 백업했습니다.
- 스크린 전체화면·소리·일시정지/재개·직접 정답 공개를 확인했습니다.
- 새 행사에 이전 수령 명단이 남아 있는지 확인했습니다.
- 운영할 진행실 하나를 정하고 진행자 전용 화면과 공개 스크린을 구분했습니다.
