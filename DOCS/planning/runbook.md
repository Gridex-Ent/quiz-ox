> 현재 앱은 클라우드 전용이다. 일반/번외 모두10초이며 노래만 시간 표시 없이 진행한다. 참가자는 시간이 끝나면 **O=주먹, X=보자기**로 손을 들고 정답까지 유지한다. 대문은 행사 설정의 이름/날짜/장소/안내와 별도 한 줄의 모양 안내를 사용한다. 행사 설정에서4MiB 이하 상품 이미지를 업로드·저장하거나 기본 이미지로 복원한다. 스크린에서 소리를 켜면 똑딱 카운트다운과 종료 효과가 재생된다. 아래 기록은 이전 단계의 이력이며 최신 실행 안내는 [README](../../README.md)를 따른다.

## 현재30·31번 누적 추가 — 파이썬·대한전기학회 로고

**‘파이썬의 로고는 뱀 두 마리이다.’ / 정답O**를 메인30번으로 추가했다. 기존29개와 순서는 그대로이며1번X·2번O도 유지한다. 주제2초 후5초 자동 타이머, 직접 정답 공개 시 공식 PSF 로고를 함께 표시한다. 정답 공개 전에는 로고를 숨겨 답을 미리 보여 주지 않는다.

후속 **31번 ‘대한전기학회 로고는 전압, 전류, 저항으로 만들어졌다.’ / 정답X**도 누적한다. 공식 CI 설명에 맞춰 **전압 단위 볼트(V)와 저항 단위 옴(Ω)을 포갠 로고**라고 정답 해설을 표시한다. 주제2초/자동5초와 정답 공개 후 공식 로고 표시를 적용한다. 최종 완료 기준은 기존29+파이썬+대한전기학회 총31개 저장·재접속·클라우드 반영·실제 출제/전환 검증이다.

완료: 두 실제 은행31개 저장/재접속·원래29개 전체prefix 및Python30 보존·회귀140개/두 빌드31개·main00011-rqp 반영을 확인했다. 클라우드에서30번O→31번X와 공식 로고/해설→종료를 검증했고 대문으로 복원했다.31번 정답 화면은1366×768·1920×1080에서 확인했다. [최종 검증](../validation/2026-10-22/main-python-logo.md).

## 메인 문제 확장 — 제주어6개와 전기국가1개

사용자가 제주 방언 문제는 **메인 OX**에 추가하도록 지정했다. 기존 본게임20문항 뒤21~26번에 제주어6개(지슬/감저/도새기/강생이/혼디/하영)를 붙이고,27번에 사용자 제공 전기국가 문항을 추가한다. A전력/B전기, 정답B‘전기’를 유지한다. 선택형 기존 엔진에서는 O쪽이A, X쪽이B이며 공개 정답은 실제 보기 ‘전기’로 표시한다. 저장된 번외33개는 그대로다.

구현·자동/실제 화면 검증·클라우드 반영을 완료했다. 기존 두 seed의20개·실제 로컬/클라우드 은행·편집 화면을 백업하고 새7개만 추가했다. 두 실제 은행은 재접속 후27개이며 기존20 전체 객체 prefix를 보존한다. 공개되는 뜻풀이와 근거를 남겼고 사회자 멘트는 관리자 note로 분리했다. 후반 메인 규칙에 따라 주제2초 후5초 타이머가 자동 시작되고 정답은 직접 공개한다. 기존 문제 선택 드롭다운에서21~27번을 바로 선택하거나20번 이후 순서대로 진행한다. 기본 문제집 재로딩 버튼은 ‘행사 기본 문제 불러오기’이며 현재 seed는27개다. ## 사용자 제공 전기 OX 드립7개 — 2026-10-22

사용자가 제공한 전기/인체 전기/전기차/태양광/전력·전력량/새와 전선/찌릿해7개를 원문과 정답 O/O/X/X/X/O/X 그대로 별도 **사용자 제공 전기 OX 드립 7개** 그룹에 추가한다. 🎤 진행 멘트는 정답 뒤에 읽을 관리자 전용 메모다. 공개 해설은 비워 두어 멘트가 참가자 화면에 나오지 않게 한다. 기존 드립8개·원본18개·본게임20개를 유지한다.

동선은 **진행 런북 → 저장된 번외 퀴즈 → 사용자 제공 전기 OX 드립 7개 → 문제 선택 → 선택한 번외 문제 출제**다. 주제2초 후5초 타이머가 자동 시작되며, 정답은 직접 공개하고 본게임으로 돌아간다. 진행자 멘트는 출제 전 미리보기와 출제 중 관리자 메모에서 읽는다.

## 진행자 드립 번외 추가 — 2026-10-22

기존 본게임20문항과 사용자 넌센스14개·경품4개를 보존하며 새 드립8개를 별도 그룹으로 추가한다. 연구비·연장선·오차·최종본·상수함수·주파수와 가벼운 말장난을 준비한다. 정답 뒤 한마디는 `hostNote`→관리자 전용 `note`에 넣고, 공개 해설과 분리한다. 새 항목은 이전 원본에서 복원했다고 표시하지 않는다.

**진행 런북 → 저장된 번외 퀴즈 → 진행자 드립 번외 8개 → 문제 선택 → 선택한 번외 문제 출제**를 사용한다. 기존과 같이 주제2초 후5초 타이머가 자동 시작되며, 시간이 끝나도 정답은 직접 공개한다. 정답을 공개한 뒤 **본게임으로 돌아가기**를 누른다. 정답 뒤 한마디는 출제 전 미리보기와 출제 중 관리자 메모에만 보인다. 일부 연구 공감형 말장난은 뜻이 통하는 다른 표현도 인정하도록 관리자 메모를 제공한다.

| 문제 | 정답 | 정답 뒤 한마디 예시 |
|---|---|---|
| 연구자들이 가장 반기는 비는? | 연구비 | 이 비는 많이 내려도 우산 안 씁니다. |
| 논문 마감 날, 연구자가 가장 갖고 싶은 전선은? | 연장선 | 전기는 됐고, 마감만 일주일 연장 부탁드립니다. |
| 연구자가 실험에서 가장 피하고 싶은 차는? | 오차 | 정답은 쉬운데, 줄이는 건 쉽지 않죠. |
| 연구실 파일 이름 중 가장 믿기 어려운 세 글자는? | 최종본 | 그 옆에 ‘진짜최종’ 파일도 있죠? |
| 미분 한 번에 0이 되어 버리는 함수는? | 상수함수 | 제 긴장도 한 번만 미분해 주시면 감사하겠습니다. |
| ‘말이 잘 통하는 사이’를 전기공학식으로 말하면? | 주파수가 맞는 사이 | 오늘은 웃음 주파수부터 맞춰 보겠습니다. |
| 세상에서 가장 뜨거운 바다는? | 열바다 | 정답 듣고 열받으시면, 문제는 성공입니다. |
| 차가 깜짝 놀라면? | 카놀라유 | 웃음이 안 나와도 분위기에 기름칠은 됐습니다. |

## 문제 준비·제출 방법

문제는 콘솔의 **문제 탭**에서 세 가지 방법으로 넣는다. 어느 방법이든 정답은 `O`/`X`, 종류는 일반 또는 부활전(패자부활전용), 제한시간은 비우면 기본값(15초)이다.

| 방법 | 언제 | 하는 법 |
|---|---|---|
| 편집기에서 하나씩 | 문제가 10개 안팎일 때, 사진 문제 | **+ 문제 추가** → 지문·정답·종류·제한시간·해설 입력 → 사진 문제는 **📷 사진 선택**으로 파일 업로드 → 저장. 목록의 **편집**으로 수정 |
| CSV 파일 | 엑셀·구글시트로 미리 정리했을 때 | 열 순서 `문제,정답,종류,제한시간,이미지,해설`(첫 줄 헤더). **CSV/JSON 불러오기** → 파일 선택 또는 붙여넣기 → 가져오기. 목록 전체가 교체된다. 예시: 저장소 `questions/sample-questions.csv` |
| 샘플로 시작 | 리허설 | **샘플 문제** 버튼 → 12개(부활전용 2개 포함)가 들어온다 |

- 사진 문제: 지문은 "이 사람은 아인슈타인이다"처럼 사진을 보고 O/X를 고르게 쓴다. 사진은 편집기에서 올리면 서버에 저장되어 행사장 인터넷과 무관하게 나온다. CSV의 이미지 열에 외부 URL을 적어도 되지만, 그 사이트가 느리거나 막히면 사진이 안 나올 수 있다. 얼굴 사진은 세로 사진보다 가로·정방형이 크게 나온다(액자 480×380).
- 부활전용 문제는 종류를 "부활전"으로 두면 목록에 ♻ 표시가 붙고, 패자부활전 시작 때 자동으로 그 문제가 나온다. 일반 문제 순서에는 끼지 않는다.
- 문제를 낸 뒤에는 삭제·순서 변경이 막힌다(진행 중 사고 방지). 지문·정답 오타는 편집으로 고칠 수 있다.
- 게임 도중 급히 문제를 추가하면 목록 맨 뒤에 붙는다.

- [ ] 콘솔 로그인 → 설정 탭: 제한시간(기본 15초), 부활전 시점(기본 5번 문제 뒤), 이동 공개 시점(기본 4번까지) 확인
- [ ] 문제 탭: 문제 가져오기 → 정답 O/X와 순서 검토. 패자부활전용 문제가 ♻ 표시인지 확인
- [ ] 설정 탭에서 **QR 이미지 저장** 후 인쇄해 배포. QR은 배포된 공개 URL의 `/join`만 담고 방 코드는 없으므로, 게임 초기화를 해도 인쇄물이 계속 유효하다. **배포 뒤에** 만들어야 주소가 맞는다
- [ ] 리허설: 본인 폰으로 `/join` 입장 → 콘솔에서 입장 마감 → 문제 1개 진행 → **게임 초기화(문제 유지)** 로 되돌리기
- [ ] 전화번호 안내 문구가 폼에 맞게 나오는지 확인 → [[ADR-0003-phone-identity]]

## 당일 순서

1. 핫스팟 켜고 노트북 연결. 백업 폰 핫스팟도 미리 켜 둔다.
2. 브라우저 창 A: `/host` 로그인(PIN). 창 B: `/screen` → 스크린 키 입력 → 프로젝터로 보내고 전체화면.
3. 스크린 오른쪽 아래 **🔊 사운드 켜기** 클릭(한 번만).
4. 스크린에 QR과 방 코드가 보이면 참가자 입장 안내. 콘솔 참가자 탭에서 인원 확인. 이름이 부적절하면 **퇴장**.
5. 규칙 멘트 3줄: "틀리면 대기실(관전), 두 번 틀리면 탈락, 중간에 패자부활전 한 번." 채팅도 안내한다: "폰 아래 채팅으로 응원하면 스크린에 말풍선으로 뜹니다."
6. **입장 마감 카운트다운** 클릭. 스크린에 10초 카운트다운이 크게 뜨고 마지막 5초는 틱 소리가 난다. "곧 마감됩니다, 지금 들어오세요"라고 안내하면 막판 참가자가 들어온다(**카운트다운 동안에도 입장은 열려 있다**). 버튼을 한 번 더 누르면 즉시 마감, 더 기다리려면 **마감 취소**. 마감 뒤에는 새 번호가 들어올 수 없고 기존 참가자의 복귀만 가능하다.
7. **1번 문제는 맛보기**다. 틀려도 아무도 떨어지지 않으니 "연습입니다"라고 안내하고 버튼 누르는 법을 보여 준다. 화면에도 초록 띠로 안내가 나온다.
8. 문제마다: **문제 공개** → (스크린에 3·2·1 준비 카운트, 타이머 자동 시작) → (자동 마감) → **정답 공개** → 해설 → **다음 문제**.
   - 큰 보라색 버튼 하나만 누르면 순서대로 진행된다. 준비 카운트 중 버튼을 누르면 즉시 시작한다.
   - 문제를 천천히 읽어 줄 시간이 필요하면 설정 탭에서 준비 카운트를 늘리거나 자동 시작을 끈다.
   - 초반 4문제는 아바타 이동이 실시간으로 보이고, 5번부터는 마감 때 한꺼번에 공개된다.
9. 5번 문제 정답 공개 뒤 큰 버튼이 **패자부활전 시작**으로 바뀐다. 대기실 인원을 확인하고 누른다.
   - 무대가 교대된다. 부활전 정답자는 무대 복귀(남은 기회 1회), 오답·미응답은 탈락.
   - 부활전을 건너뛰려면 옆의 "부활전 없이 다음 문제".
10. 무대 생존자가 **3명 이하**가 되면 정답 공개 6초 뒤 자동으로 "🎉 축하합니다!" 화면으로 넘어가 결승 진출자의 이름과 휴대폰 뒷번호 4자리가 크게 뜬다. 뒷번호로 본인을 확인해 무대로 부른다.
   - 그 시점에 패자부활전을 아직 안 열었고 대기실이 있으면 큰 버튼이 **패자부활전 시작**으로 바뀐다. 부활전을 먼저 하고, 그 결과 3명 이하면 축하 화면으로 간다.
   - 6초를 기다리지 않으려면 큰 버튼 "지금 발표", 취소하려면 "다음 문제" 또는 "판정 취소".
   - 문제가 끝났는데 생존자가 4명 이상이면 **게임 종료**를 눌러 생존자 명단을 띄우고 무대에서 정리한다.
11. 무대에서 추가 문제·가위바위보로 결승(앱 밖). 끝나면 콘솔에서 **우승자 지정** → 카드에 왕관.

## 사고 대응

| 상황 | 대응 |
|---|---|
| 정답을 잘못 입력한 채 공개했다 | **판정 취소** → 문제 탭에서 정답 수정 → **정답 공개** 다시. 탈락자는 자동 복귀 |
| 참가자가 "눌렀는데 안 됐다"고 항의 | 콘솔 참가자 탭에서 그 사람의 선택 열을 확인. 미응답이면 규칙대로 오답. 네트워크 사고가 분명하면 **복구** |
| 부적절한 채팅이 올라왔다 | 콘솔 **채팅 탭**에서 그 줄의 ✕로 삭제(스크린·폰에서 즉시 사라짐). 계속되면 **🔒 채팅 잠그기**, 도배한 사람은 참가자 탭에서 퇴장 |
| 여러 명이 동시에 못 답했다(핫스팟·통신 장애) | 답변 중이면 **라운드 취소** → 타이머 다시. 이미 공개했으면 **판정 취소** 후 라운드 취소 |
| 노트북 인터넷이 끊겼다 | 백업 핫스팟으로 전환. 서버는 클라우드에 있어 참가자 진행은 유지되며 콘솔·스크린은 자동 재접속 |
| 참가자 폰이 꺼졌다/새로고침했다 | `/join`에서 같은 번호·같은 이름으로 다시 입장하면 자리가 복구된다 |
| 탈락자가 항의한다 | 콘솔 참가자 탭 → **복구**(탈락 → 대기실) |
| 무대 생존자가 0명이 됐다 | 콘솔 경고가 뜬다. 대기실이 있으면 **추가 부활전(비상용)**, 없으면 **판정 취소** 또는 종료 |
| 문제가 바닥났는데 생존자가 많다 | 문제 탭 **+ 문제 추가**로 즉석 출제(뒤에 붙는다) 또는 종료 후 오프라인 결승 |
| 스크린 창이 프로젝터에서 사라졌다 | `/screen` 다시 열기. 현재 상태로 즉시 복원된다(연출 없이 배치) |
| 서버가 재시작됐다 | 마지막 상태로 복구된다. 답변 중이었다면 문제 화면으로 돌아오니 타이머만 다시 시작 |
| 콘솔 PIN을 5번 틀려 잠겼다 | 10분 뒤 다시 시도. 급하면 다른 네트워크(폰)로 접속 |

## 행사용 아바타 봇 (초반 무대 채우기)

실제 참가자와 함께 뛰는 가상 참가자 10명. 각자 정답률(기본 70%±20)이 달라 자연스럽게 갈리며, 시간을 끌다 고르고 가끔 마음을 바꾼다. **5번 문제 정답 공개까지 함께 뛰고 3초 뒤 명단에서 조용히 사라진다**(탈락으로 집계되지 않음, CSV에도 남지 않음). 우승할 일도 없다.

```bash
# 사회자 노트북에서, 입장 접수 중에 실행. 서비스 URL·PIN을 실제 값으로.
npm run bots -- --count 10 --until 5 --url https://<서비스URL> --pin <사회자PIN>
```

- 이름은 민준·서연·도윤·하은·지호·수아·예준·지우·시우·하윤 순으로 고정이며 번호는 `0108-100-000x` 가짜 번호다.
- 정답을 읽기 위해 사회자 PIN이 필요하지만 진행 명령은 절대 내리지 않는다.
- 콘솔에서 **게임 초기화**를 하면 봇들이 알아서 다시 입장한다. 끝까지 같이 뛰게 하려면 `--until 0`.
- 본행사 D-1 리허설에서 봇만으로 한 번 끝까지 돌려 보면 콘솔 버튼 순서가 손에 익는다.
- 봇만으로 **한 판을 자동으로** 돌려 보려면 `npm run autoplay`(사회자 조작을 대신한다). 이때 봇은 끝까지 뛰도록 `--until 0`으로 띄운다. 실제 행사에서는 쓰지 않는다.

```bash
npm run bots -- --count 10 --until 0     # 끝까지 뛰는 봇
npm run autoplay                          # 입장 마감 → 문제 → 부활전 → 결승까지 자동
```
