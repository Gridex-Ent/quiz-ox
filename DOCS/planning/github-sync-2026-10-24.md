# 원격 이력·로컬 작업 보존 통합

## 후속 범위 — 클라우드 전용·범용 행사 설정

사용자 후속 지시에 따라 최종 앱은 클라우드 진행실/공개 스크린만 남긴다. 구 참가자 React/서버·단독 오프라인 HTML/실행기·낭독 음성 산출물은 최신 tree에서 제거하되 원격 과거 커밋과 원본 snapshot을 보존한다. 현재 cloud가 공유하는 퀴즈 모델/표시/런북/음향/편집 모듈은 공통 엔진으로 유지한다. 기존31문항·번외33개·상품/명단·인증·문제 저장은 그대로다.

추가 지시: 참가자 응답은 왼손/오른손 대신 **O=주먹, X=보자기**로 고정한다. 선택형의 첫 보기(choiceO)도 주먹, 둘째 보기(choiceX)는 보자기로 표시한다. 보기 배치를 바꿔도 응답 모양의 의미는 바뀌지 않는다. 공개 문구·대문·게임 안내에서 손 방향을 없애고 **시간이 끝나면 해당 모양으로 손들기 → 정답 공개까지 유지**를 안내한다. 문항 정답/순서와 O/X 내부 모델은 바꾸지 않는다.

후속 확정: 일반 메인/번외 시간을 모두 **10초**로 통일한다. 노래 문제는 기존 시간 표시 없음 정책을 유지한다. 공통 questionSeconds·문서/seed·번외 생성/재개와 대문/진행실 안내를 함께 갱신한다. 카운트다운은 매초 번갈아 나는 똑딱 효과음을 공통 sound.tick에서 합성하며, 중복 tick 방지·종료/정지/재연결·스크린에서 명시적 소리 켜기 경계는 유지한다.

주먹/보자기 문구는 사용자 안내 문구와 분리해 그 아래 전용 한 줄로 표시한다. 줄바꿈 없이 읽히도록 반응형 크기를 제한한다.

상품 소개는 event와 별도 `prize: null | {imageData,imageAlt,caption}`을 schema1 문서에 호환 추가한다. 업로드는 PNG/JPEG/WebP/GIF의 내장 원본 이미지로 decoded4MiB/URI6MiB 이내, 서버에서 base64·형식·signature를 검증한다. 관리자 action `{type:'prize',prize}`는 기존 세션/revision/CAS/ACK를 사용하며 은행·명단은 건드리지 않는다. null은 내장 기본 이미지로 복원한다. `prize-settings.js`는 파일/초안·미리보기/저장·실패/타탭 충돌·늦은 파일 읽기/ACK 중 편집 보존을 소유한다. transport가 서버 확정값만 전달하고 공개 DTO의 상품 설정은 이미지/alt/캡션만 허용한다. 상품 단계는 큰 이미지와 캡션만 표시해 기존 특정 행사 금액/등수 목록을 고정 출력하지 않는다.

큰 이미지 반복 전송 방지를 위해 별도 prizeVersion(이전 문서 누락0)을 둔다. 관리자 폴링의 prize 버전과 서버 버전이 다를 때나 최초/상품 저장/불확실 결과 복구에만 이미지 본문을 전달하고, 일반 진행 ACK는 이미지 없이 버전만 보낸다. transport는 누락값과 명시적null(기본복원)을 구분해 캐시·동기화를 유지한다. 공개 화면에도 상품 단계에서만 상품 이미지 본문을 제공한다.

진행실 미리보기/스크린의 큰 이미지 HTML은 revision 또는 표시 초가 바뀔 때만 재생성한다. 100ms 음향/시계 루프는 유지해 효과음 시점을 놓치지 않되 매 프레임 수 MiB 이미지 문자열을 다시 escape하지 않는다.

추가 완료 기준: 기존31문항 전체 객체에서 seconds만10으로 정규화·번외33 유지 → 상품 업로드/복원/재시작/권한/실패 검증 → 카운트다운 중복 없는10tick/완료 효과 검증 → 실제 브라우저 대문10초 설명·메인/번외 자동10초·주먹 안내 한 줄·상품 업로드/새로고침·스크린 표시 확인 후 발행한다.

| 모듈 | 추가 책임 / 공개 인터페이스 |
|---|---|
| 행사 데이터/서버 | `event: {name,date,venue,message}`를 schema1 문서에 호환 추가. 기존 문서의 누락 값은 범용 기본값. 기존 인증 action `{type:'event',event}`·revision/CAS/ACK로 저장하며 은행/명단은 변경하지 않음 |
| 진행실 | 행사 설정 화면에서 행사명/날짜/장소/안내 문구 입력·명시적 저장. 전송/실패/새로고침 상태를 표시하며 미저장 입력을 폴링으로 덮지 않음 |
| 공개 표시 | 공개 DTO의 허용된 행사4필드를 대문과 종료 화면에 HTML escape해 반영. 공개 날짜/장소만 표시하며 관리자 데이터는 제외 |
| 빌드/런타임 | root package·lock·Docker·배포 허용목록을 cloud 단일 앱에 맞춤. 구 오프라인/참가자 entry 제거, 기존 cloud seed31개 사용 |

검증: 기존 저장 문서 호환·설정 저장/실패/충돌·정답/명단 비공개·회귀/두 target build → 실제 진행실 설정 저장/새로고침과 별도 스크린 반영/표시 → 원격 통합 커밋/push. 기존 운영 Cloud 반영은 인증/배포 완료 여부와 GitHub 소스 반영을 구분해 기록한다.

사용자가 origin을 `https://github.com/Gridex-Ent/quiz-ox.git`로 변경하고 원격 커밋과 최신31문항·클라우드 소스를 함께 보존해 커밋/push하도록 승인했다. 시작 로컬 main은 `ee085c9`, 원격 main은 직전 조회 `f20163a`로4커밋 앞선 상태다. 현재 추적 수정10개·미추적201개를 먼저 ignored `data/git-sync/`의 바이트/해시 snapshot과 Git bundle로 보존했다. ignored 런타임 상태·PIN·연결 키·개인 명단은 원래 위치에 그대로 두고 발행 대상에서 제외한다.

| 책임 | 범위 / 인터페이스 | 의존 |
|---|---|---|
| 원본 작업 보존 | main 작업트리를 reset/clean하지 않고 전체 수정/미추적 snapshot·이력 bundle 보존 | 로컬 Git/파일 |
| 원격 이력 통합 | origin URL 변경·fetch 후 원격 main에서 별도 worktree/통합 branch 생성, 원격 커밋을 조상으로 보존 | Git CLI, 승인된 저장소 |
| 최신 앱/데이터 | 두 seed31개, 번외33개, 자산/빌드/서버/화면/기존 문서의 현재 내용을 적용. 겹치는 원격 수정은 내용 비교로 해결 | 기존 모듈/API 재사용 |
| 발행 검증 | PIN·키·명단·로컬 상태 제외, 필수 자산/문서 포함, 회귀/빌드/형식 검사 | 안전 검토·별도 worktree |
| GitHub 반영 | 보호된 원격 이력을 강제로 바꾸지 않는 정상 push, 최신 원격 SHA/내용 재조회 | 원격 main |

단계: 보존 snapshot → origin/fetch·원격 차이 분류 → 별도 통합 worktree에서 충돌 해결 → 발행 범위/개인 데이터 점검 → 검사·두 빌드 → 커밋·정상 push → 원격/원본 보존 확인·대시보드 갱신. 기존 Cloud Run/상태/예약 변경이나 재배포는 이번 범위에 포함하지 않는다. 원격의 과거 음성 이력은 보존하며 최신 실행은 사용자가 선택한 수동 진행/효과음 방식이다.

완료 기준은 원격의 기존4커밋과 시작 로컬 HEAD를 모두 조상으로 갖는 발행 HEAD, 최신31개 seed·클라우드 소스/필수 자산 포함, 검증 결과와 원본 snapshot의 무손실 확인이다. 단순 소스 발행 결과를 새 클라우드 배포·현재 가동 검증으로 표현하지 않는다.

진행자 팁: 사용자 제공 무대 인원 조정 멘트를 진행실 전용 panel에 원문 그대로 표시한다. host HTML은 기존 관리자 인증 경계 안에 두고 public renderer/DTO/스크린 번들에는 문구를 넣지 않는다.
