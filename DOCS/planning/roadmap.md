# 클라우드 전용 전환 로드맵

## 선택형 문제은행 — 2026-10-24

진행실과 행사 설정에서 공통 문제은행 탭으로 이동해 후보70개 중 체크한 문제만 현재 편집란 끝에 추가한다. 기존31문항·서버에 확정된 문제집·작성 중 편집은 보존한다. 가져오기는 초안에만 반영하고 기존 `문제·순서 저장`의 서버 ACK·충돌 처리를 통해 확정한다. 운영 배포는 하지 않는다.

| 영역 | 소유 모듈 / 공개 인터페이스 |
|---|---|
| 후보 데이터 | `questions/catalog.json`: 안정적인 id, 주제·지문·정답·해설·출처를 가진 범용 OX70개 |
| 선택·가져오기 | `question-bank.js`: `createQuestionBank({root,catalog,getDraft,onImport,onEdit})`; 필터와 선택 상태, 중복 방지, 최대300개·기존 초안 보존 |
| 진행실 연결 | `presenter.js`와 `host-shell.html`: 탭·설정 바로가기, 편집 초안 추가/보관과 기존 저장 흐름 연결 |
| 서버·스크린 | 새 API 없이 기존 apply·revision/CAS/ACK 사용. 후보 전체와 진행자 정답은 공개 스크린에 보내지 않음 |

단계: ① 후보/인터페이스 설계 → ② 출처를 확인한 후보70개와 체크박스 UI → ③ 초안 보존·필터/선택·중복/저장 경계 자동 검증 → ④ 휴대폰/노트북 실제 브라우저 확인 → ⑤ 매뉴얼·대시보드 갱신과 commit/push. 1~4단계 및 문서 갱신 완료, 전체185개·lint/build와1366/390 화면을 통과했다. 소스·문서·검증 기록을 함께 Git 발행 대상으로 확정했다. [검증](../validation/2026-10-24/question-bank.md). 운영 배포는 이번 범위 밖이다.

## GitHub 첫 화면·공개 매뉴얼 — 2026-10-24

사용자가 배포는 필요 없다고 명시했다. 이번 범위는 README를 GitHub 저장소 첫 화면의 프로젝트 소개/실행/메뉴별 사용 안내로 정리하고, 독립 사용자 매뉴얼과 저장소 About 설명을 연결한 뒤 commit/push·원격 표시를 확인하는 문서 작업이다. root는 README/About·대시보드/발행을, 문서 담당은 `DOCS/USER_GUIDE.md`의 실제 코드 기준 사용 설명을 소유한다. 코드·Cloud Run·인증은 변경하지 않는다. 단계는 현재 SHA 확인 → 문서/설명 갱신 → 링크·문구·민감값 검사 → 커밋/push → GitHub main의 렌더링 확인이다.

완료: 문서 커밋 `00463f1`을 main에 정상 push했다. 상대 링크39개와 민감값 제외를 검사했고, 실제 GitHub에서 About·README·이미지2개·Mermaid·상세 매뉴얼 링크 및 본문 표시를 확인했다. 문서 작업 중 앱 코드는 변경하지 않았으며 운영 배포도 하지 않았다.

휴대폰 진행실과 읽기 전용 스크린을 하나의 서버 상태로 운영한다. 행사 정보와 O 주먹/X 보자기 안내를 범용화하고 기존31문항·번외33개·상품·명단·음향·수동 정답 인터페이스를 보존한다. [모듈 설계](../design/manual-cloud.md)를 기준으로 진행하며 전체 현황은 [대시보드](../index.md)에서 관리한다.

## 보존·저장 기준

- 기존 메인31문항의 문구·정답·순서·사진·영상·메모와 번외33개를 보존한다.
- 첫 주제는 워밍업2초다. 일반/번외 모두10초, 노래 무타이머와 직접 정답 공개를 유지한다.
- 행사 정보는 이름/날짜/장소/안내 문구로 관리한다. 기존 저장값에 행사 정보가 없으면 범용 기본값을 사용하며 문제집·명단은 기존 저장값을 보존한다.
- 운영은 GCS 조건부 저장·PIN/IAP 진행실·키를 사용하는 읽기 전용 스크린 경계를 유지한다. 개발 PIN/키와 상태는 ignored 개발 프로필에만 저장한다.
- 과거 단독 HTML·음성·React/참가자 서버의 실행 코드는 삭제 대상으로 정리하고 검증·설계 문서는 역사 자료로 남긴다.
